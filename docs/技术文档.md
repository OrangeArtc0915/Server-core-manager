# Textm 2.0 技术文档

本文说明 Textm 2.0 的技术栈与实现方法，重点覆盖：
类 Windows Terminal 的终端渲染/输入实现、图片与富文本显示方案、SCM（Git）集成方案。

> 约束：只能在 Windows Server Core 上运行；单文件 exe；
> 除插件使用的纯 Rust JS 引擎 Boa 外不引入第三方依赖；
> 同时提供终端（TUI）与图形（GUI）两种形态。

---

设计原则：

1. **渲染与后端解耦**：编辑器只生成 `Canvas`（字符单元网格），TUI 把它转成 ANSI，
   GUI 把每个单元画成等宽字形。布局、浮层、主题只写一份。
   `render.rs` 用统一的圆角边框 / 阴影 / 状态胶囊绘制 chrome，编辑器文本区
   在布局阶段向内缩进 1 格，保证边框不覆盖内容；`icons.rs` 自动选择 Nerd Font
   或 Unicode / ASCII 图标。界面提供两套可切换布局（配置项 `layout`）：
   **VSCode（默认）**——顶部菜单栏、顶部标签栏、左侧 3 列活动栏、底部状态栏；
   **sqlmux**——没有顶部栏，侧栏与编辑器是两个带圆角边框的 pane（标题嵌在上边框、
   右侧画键位提示），两 pane 之间留 1 列间隙，标签行位于各自 pane 内部最后一行。
   `Layout::compute_ext` 按 `LayoutStyle` 计算两套几何（`menu / tabs_top / activity`
   等字段），渲染与鼠标命中共用同一份矩形；`F4` 打开菜单浮层，`F1` 打开 which-key 速查。
2. **尽量零依赖**：编码转换、正则、压缩、XML、JSON、LSP、Git 都自己实现或调用系统组件；
   只有插件 JS 引擎使用 Boa（纯 Rust，随 exe 静态链接，不需要 Node）。
3. **中文优先**：列号按 Unicode 字符计，宽字符占两格，Tab 按显示列对齐。

## 2. 类 Windows Terminal 的终端实现方法

### 2.1 渲染模型

Windows Terminal 的核心是「VT 解析 → 屏幕模型 → 前端渲染」。Textm 的 TUI 后端
采用同一思路的简化版：

- **输出**：开启 `ENABLE_VIRTUAL_TERMINAL_PROCESSING`，用 SGR 真彩序列
  （`38;2;r;g;b` / `48;2;r;g;b`）绘制；备用屏幕 `?1049h` 保存原控制台内容。
- **屏幕模型**：`render::Grid` 保存每个单元的前景/背景/属性/宽字符标记。
- **差分刷新**：每帧与上一帧比较，仅重写发生变化的行；输出合并为一次
  `WriteConsoleW`，避免闪烁与高频系统调用。
- **宽字符**：宽字符占两个单元，第二格标记为 `cont`，渲染时跳过；
  `unicode.rs` 维护东亚宽字符区间表。

### 2.2 输入

不使用 ANSI 输入解析，而是 `ReadConsoleInputW`：

- 键盘事件带 `wVirtualKeyCode`、`UnicodeChar`、`ControlKeyState`，能正确处理
  Ctrl/Alt/Shift、AltGr、输入法提交的中文、Alt+字母。
- 鼠标事件直接给出**字符单元坐标**，不需要自己换算像素。
- `WINDOW_BUFFER_SIZE_EVENT` 提供窗口缩放，界面按新尺寸重排。

TUI 与 GUI 共用 `console::{Key, KeyCode, Mods, Mouse, MouseKind}` 事件类型，
`ui::app` 只处理这一套抽象。

鼠标交互与 sqlmux 的「键位提示即按钮」一致：

- `App::hints()` 同时产出所有可点击提示条的矩形与动作（面板标题右侧、标签行
  右侧、状态栏左侧），渲染只负责按矩形画，命中测试直接查同一份数据，两者不会
  走样；悬停时用 `mouse_pos` 给出强调底色。
- `App::status_items()` 产出状态栏右侧信息段（行列 / 编码 / 换行 / 语言 / 错误与
  警告计数），点击分别执行转到行、编码选择器、换行符选择器、语言选择器、问题列表。
- 行号槽：点行号选中整行，点最左标记列切换断点；小地图按纵向比例跳转，支持拖动。
- 右键弹出 `Overlay::Context`（编辑器 / 标签 / 资源管理器各自的菜单），
  键盘 ↑↓/Enter/Esc 与鼠标共用同一浮层。
- VSCode 布局额外支持：顶部菜单名点击打开下拉菜单（`menu_bar_items` 与绘制共用
  矩形）、顶部标签点击 / 拖动排序 / 中键关闭、活动栏切换三个侧栏视图或打开设置、
  面包屑点击打开符号大纲（右侧语言名打开语言选择）。
- 轻量动效由 `App::tick`（约 60ms 一帧）驱动：`pulse` 三角波用于光标呼吸底色与
  选中条；`status_at` 控制状态消息 4 秒后淡出、8 秒后隐藏并恢复键位提示。
  悬停高亮直接读取 `mouse_pos`，不额外分配缓存；ristretto 等主题通过
  `hover_bg / raised_bg / divider` 统一派生悬停、抬起与分隔线颜色。
- **欢迎页**：空白、未命名、未修改的普通文档由 `App::is_welcome_tab` 识别，
  `App::welcome` 按文本区居中返回卡片与快捷入口矩形，渲染和鼠标命中共用；
  入口直接映射到 `HintTarget`（快速打开 / 命令面板 / 打开文件 / 设置 / 键位），
  开始输入即自动消失。
- **模糊高亮**：命令面板与快速打开的标题按查询做子序列匹配，
  `title_highlighted` 把命中的字符染成强调色；查询前缀（`>` / `@` / `#`）先剥离。

### 2.2.1 Vim 模态（`core::vim`）

- `Vim::handle` 只接受 `Document`，返回 `Action`（改文档 / 打开 Ex 命令行 /
  搜索 / 半页滚动 / 分屏 / 切标签 / 状态提示），界面层负责执行这些动作。
- 按键状态机：数字前缀 → 操作符（d/c/y/>/</g~…）→ 动作或文本对象；
  寄存器、宏（`q`/`@`）、标记、`.` 重复都在引擎内维护。
- 插入模式复用原有的直接输入逻辑，`:w` / `:s` / `:set` / `:sp` 等在
  `ui::commands::exec_ex` 中实现，`s/旧/新/g` 走 `regex_lite` 正则引擎。

### 2.2.2 分屏与终端

- 布局支持 1–2 个编辑器 pane（左右或上下，中间 1 列 / 1 行间隙），
  每个 pane 有独立的标签行、面包屑、行号槽与小地图；`App::pane_views`
  把“分组 → 标签 → 几何”三者对应起来，渲染和鼠标命中都查同一份数据。
- 终端面板用 ConPTY（`CreatePseudoConsole` + `CreateProcessW` 属性列表），
  读线程把输出写进最小 VT 解析器（`platform::term::Screen`），支持
  SGR 真彩、光标定位、清屏、滚动与 UTF-8；键盘输入按 ANSI 序列写回。
- 设置页是整页模态：`SETTING_CATEGORIES` 定义分类与条目，`App::settings_rows`
  产出当前分类（或搜索过滤后）的行与实时值，渲染与鼠标命中共用同一份数据；
  调整即改写 `Config` 并走 `after_setting_change` 统一刷新（主题、标签、布局）。

### 2.2.3 VSCode 对齐的子功能

- **命令面板**：`ListState::refilter` 先剥离 `>` / `@` / `#` 前缀再匹配；
  `>` 切到命令列表，`@` 打开当前文件符号，`#` 请求工作区符号，`:` 打开转到行。
  `App::recent_commands` 记录最近执行的 8 条命令，`open_palette` 把它们置顶。
- **问题面板**：`open_problems` 把 TODO / FIXME、行尾空白、LSP 诊断与插件问题统一
  映射为 1–4 级严重度；列表内 `Tab` 循环“全部 / 错误 / 警告 / 信息 / 提示”过滤；
  `problem_counts()` 汇总 LSP 与插件的错误 / 警告数，状态栏显示并可直接点击打开。
- **定义预览**：`Alt+F12` 请求 `textDocument/definition`，读取目标文件并截取定义处
  前后各 4 行放入 `ListKind::LspInfo` 浮层；列表项带 path / line，回车即跳转。
- **标签管理**：标签支持拖动排序（`move_tab` 同步修正 `active` 与分屏 `groups` 下标）；
  放不下时右侧绘制 `»`，点击打开 `ListKind::Tabs` 标签列表；右键菜单新增
  “在右侧拆分 / 在下方拆分 / 移动到另一组”。

### 2.3 GUI 窗口后端

GUI 模式不引入任何 UI 框架：

- `RegisterClassExW` / `CreateWindowExW` 创建窗口，`GetMessageW` 消息循环。
- **双缓冲**：`CreateDIBSection` 建 32bpp 自上而下 DIB，GDI 绘制完成后一次
  `BitBlt` 到窗口，避免闪烁。
- **字体度量**：`GetTextMetricsW` 取行高，`GetTextExtentPoint32W("W")` 取等宽步进，
  再用「中」字的宽度校正为两格；每个单元单独 `ExtTextOutW`，保证中文与英文严格对齐。
- **键盘**：`WM_KEYDOWN` 映射功能键与 Ctrl/Alt 组合，可打印字符交给 `WM_CHAR`，
  输入法提交的文本也走 `WM_CHAR`。
- **DPI**：进程启动时 `SetProcessDPIAware()`，避免系统缩放导致模糊。
- **图片**：解码后的 RGBA 复制到 32bpp DIB，`StretchBlt(HALFTONE)` 等比缩放绘制。

### 2.4 如果要做「真正的终端」

若把 Textm 的渲染层用于终端模拟器，还需要：

1. **ConPTY**：`CreatePseudoConsole` + `ResizePseudoConsole` + 进程属性
   `PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE`。
2. **输出泵**：重叠 I/O + IOCP 单工作线程处理所有窗格；进程退出与取消事件用
   `RegisterWaitForSingleObject` 监听，回调里 `CancelIoEx`。
3. **屏幕模型**：完整 VT 状态机（光标、SGR、滚动区、备用屏幕、OSC、DCS）。
4. **会话接管**：服务端持有窗格与会话注册表，客户端断开只摘除客户端；
   attach 时重放屏幕快照或输出缓冲。
5. **性能**：按行差分、脏区合并、批量写入；必要时 DirectWrite + Direct2D 做字形缓存。

同目录的 `TUI_TOOL/Terminal` 项目是这套方案的完整实现（ConPTY、IOCP、ScreenDiff、
多客户端 attach、亚克力背景板、DirectWrite 文本后端），可作为参考。

### 2.5 性能取舍

| 项 | 选择 | 原因 |
|---|---|---|
| TUI 颜色 | 24 位真彩 SGR | 现代 conhost/Windows Terminal 均支持 |
| 帧刷新 | 行级差分 | 打字时只重绘 1–2 行 |
| 高亮 | 按行缓存 + 状态传播 | 只重新词法分析变化的行 |
| 视觉行 | 仅变化时重建 | 折叠/换行/尺寸变化才重算 |
| GUI 文本 | 单元级 ExtTextOutW | 保证中文对齐，3000 单元耗时仍在毫秒级 |

## 3. 图片与富文本显示方案

### 3.1 解码（零依赖）

- 动态 `LoadLibraryW("gdiplus.dll")`，`GetProcAddress` 取
  `GdipCreateBitmapFromFile` 等函数（注意 `GetProcAddress` 只接受 ANSI 名称）。
- `GdipBitmapLockBits` 以 `PixelFormat32bppARGB` 读取，内存为 BGRA，转换为 RGBA。
- 图像对象缓存于标签页；GUI 再把 RGBA 复制到 DIB，TUI 直接采样。

### 3.2 TUI 显示

| 方案 | 条件 | 说明 |
|---|---|---|
| 半块字符 `▀` | 任何支持真彩的终端 | 默认方案：上像素作前景、下像素作背景，无需终端协议 |
| Sixel | 支持 Sixel 的终端 | DCS 图像数据，适合照片 |
| Kitty graphics | Windows Terminal / kitty 系 | `ESC_G` 传输 + 放置命令 |
| iTerm2 inline image | iTerm2 / WezTerm | OSC 1337 `File=...:base64` |

Textm 当前实现半块预览（`render.rs::draw_image`），并按 `WT_SESSION` 等环境变量
预留协议探测；半块方案在 Server Core 的 conhost 上也能直接工作。

### 3.3 GUI 显示

`StretchBlt` 等比缩放到文本区域居中显示，`HALFTONE` 模式做插值；
图片与原文件路径一起缓存，切换标签时只重建一次位图。

### 3.4 Word（WordprocessingML）

- **容器**：`archive.rs` 解析 ZIP 中央目录；读取支持 DEFLATE（自研 inflate：
  存储块、固定 Huffman、动态 Huffman），保存统一使用「存储」方式，Office 可正常打开。
- **XML**：`xml.rs` 是保留未知元素/属性的轻量 DOM，序列化时转义文本与属性。
- **模型**（`word/model.rs`）：
  - `styles.xml`：`docDefaults`、段落/字符样式、`basedOn` 继承链；
  - `numbering.xml`：`abstractNum`/`num`、`lvlText` 的 `%1..%9`、编号格式；
  - `sectPr`：页面尺寸、页边距、页眉页脚引用、首页不同；
  - 表格：`tblGrid`、`gridSpan`、`vMerge`、`shd`、`tcBorders`；
  - 图片：`wp:inline` / `wp:anchor` + `r:embed`，EMU → px（/9525）；
  - 域：`fldSimple` / `fldChar`，支持 `PAGE` / `NUMPAGES`；
  - 批注：`comments.xml` 关联到段落。
- **排版**（`word/layout.rs`）：
  - twips → px（15 twips/px，96 DPI），A4 默认 11906×16838 twips；
  - 字体 pt → px（×4/3），行距 Auto / Exact / AtLeast，首行 / 悬挂缩进；
  - 段落分行、表格行布局、跨页分页、表头重复；
  - 页眉页脚按节绘制，页码占位符替换；
  - 文本度量通过 `measure::Measurer` 抽象：GUI 用 GDI（`CreateFontW` /
    `GetTextExtentPoint32W` / `GetTextMetricsW`），测试用近似度量。
- **编辑**：文本视图按段落对齐，未改动段落原样保留；文本变化重建 `w:r/w:t`，
  样式变化只更新 `w:rPr`；表格、图片、页眉页脚等部件原样保留。
- **呈现**：GUI 页面视图（`gui/word.rs`）用 GDI 逐项绘制文本、矩形、图片，
  双缓存布局键（标签、修订号、缩放、宽度、行高）；TUI 保持可编辑简化视图。

### 3.5 Excel（SpreadsheetML）

- **模型**（`xlsx/mod.rs`）：`Workbook` / `Sheet` / `Cell{text,formula,style}`；
  工作表保留原始 XML 根节点，只更新变化的 `<c>`。
- **样式**（`xlsx/styles.rs`）：解析并追加 `numFmts` / `fonts` / `fills` /
  `borders` / `cellXfs`；提供数字/日期/百分比/货币格式、字体颜色、填充、边框、
  对齐；未知部件（`dxfs` 等）原样保留。
- **公式**（`xlsx/formula.rs`）：递归下降解析器，`Value::{Number,Text,Bool,Error,
  Empty,Range}`；支持区域、跨表引用、比较运算、错误值；90+ 函数
  （SUM/SUMIF/SUMIFS、AVERAGEIF、COUNTIFS、VLOOKUP/HLOOKUP、INDEX/MATCH、
  MEDIAN/STDEV、文本/日期/财务/信息函数等），带循环检测。
- **结构操作**：插入/删除行列时平移公式引用（越界变 `#REF!`），
  迁移合并区域、行高、隐藏集合；筛选与排序作用于已用区域。
- **渲染**：
  - TUI：可变列宽（字符单位换算）、合并单元格、冻结行列、选区、填充色、
    数字右对齐；
  - GUI（`gui/excel.rs`）：像素级网格，列宽 `width*7+5`，行高 pt→px；
    字体/字号/粗斜体、填充、边框、对齐、合并、冻结窗格、选区与活动单元格边框；
    鼠标命中测试、拖动选区、表头选择、双击编辑、滚轮滚动。
- **保存**：只改写变化单元格，合并区域、条件格式、图表、绘图等元素不动；
  公式同时写入 `<f>` 与缓存 `<v>`。

### 3.6 语言扩展点

- `core/language_ext.rs` 扫描 `%APPDATA%\Textm\languages\*.ini`：
  `name` / `extensions` / `keywords` / `types` / `comment` / `style`；
- 语言名、关键字与扩展名泄漏为 `'static`，注册进 `language.rs` 的全局表，
  `Language::Custom(u16)` 与内置语言共用 `keywords()/types()/label()` 接口；
- `style` 决定高亮策略：`c_like`（C 系）、`hash`（通用脚本单行注释）、
  `markup`（HTML/XML）、`plain`；
- `snippets.ini` 按小节定义用户片段，注册到 `snippets.rs` 的全局表，
  与内置片段一起出现在 `Ctrl+Shift+O` 列表中；
- 扩展只影响解析与高亮，不引入任何动态库或第三方依赖。

### 3.7 查找 / 替换与工程搜索

- `core/regex_lite.rs` 在 AST 匹配状态中携带捕获组区间（`State { pos, caps }`），
  支持 `(...)` 捕获、`(?:...)` 非捕获、嵌套组与未参与匹配的可选组；
  每个起始位置取最长结束位置，捕获组取自该路径。
- `core/search.rs`：
  - 字面量模式预存小写 needle，单行内只做一次大小写折叠；
  - `find_all_in_line` / `replace_in_line` 每行只收集一次 `Vec<char>`，
    避免“每个匹配重新收集整行”的 O(k·n) 分配；
  - 替换串展开支持 `$1..$99`、`${n}`、`$&`/`$0`、`$$` 与 `\n \t \r \\` 转义，
    编辑器内替换与工程替换共用同一实现。
- `ui/workspace.rs`：
  - 字节级预筛：字面量模式用完整查询串，正则模式用表达式开头必含的字面量前缀
    （`Regex::prefix()`），不匹配的文件直接跳过解码；
  - 正则在整段文本上扫描，天然支持跨行（`\n`、`\s` 可匹配换行），
    `^`/`$` 采用多行语义（行首/行尾）；再用行首下标数组把字符偏移映射回行列；
  - UTF-16 文件不再因 NUL 字节被误判为二进制：`Encoding::is_utf16` 先识别，
    识别为 UTF-16 时跳过字节级预筛并正常解码参与搜索；
  - `std::thread::scope` 按文件分块并行（最多 8 线程，文件数 < 64 时单线程），
    结果按文件顺序合并，保持原有排序；
  - 同一行的多个命中共享 `Arc<str>` 行文本，避免重复分配；
  - 替换在线程内完成“读取 → 替换 → 按原编码/换行写回”，
    正则模式用 `replace_in_text` 整段替换，字面量模式逐行替换以省去整段大小写折叠；
    主线程只负责合并统计与刷新已打开标签；
  - 有未保存改动的打开文件不写盘：`dirty_tab_edits` 生成编辑后走
    `replace_ranges_each` 应用到编辑器（可撤销），状态栏单独统计“内存中替换”。
- `core/glob.rs`（零依赖的路径过滤）：
  - `glob_match` 支持 `*`（不跨 `/`）、`**`（跨目录）、`?`（单个非分隔符字符）；
  - `match_patterns` 处理逗号/分号分隔的多个模式：不含 `/` 的模式按文件名匹配，
    含 `/` 的模式按相对工程根目录的路径匹配；
  - `IgnoreRules` 读取工程根目录 `.gitignore`：跳过空行与 `#` 注释，支持 `!` 否定、
    末尾 `/` 目录规则与后匹配优先；目录规则同时匹配自身与任一祖先路径。
  - `workspace.rs` 在 `collect_files` 之后统一过滤：先 `.gitignore`，再包含 glob，
    最后排除 glob；搜索与替换共用同一份过滤结果。
- 搜索历史：成功执行搜索后写入 `config.search_history`（去重、最新在前、上限 10），
  在搜索面板按 `↑`/`↓`（结果为空时）召回，持久化为 `search0..search9`。

编辑器输入层：`auto_pair` 控制自动闭合括号/引号（输入闭符号时若右侧相同则跳过），
Ctrl+D 为 VS Code 风格的“选中下一个相同内容”（整词匹配、不循环），
工程搜索面板支持 Alt+C 区分大小写、Alt+W 全词匹配、Alt+G 切换 .gitignore。

### 3.8 编辑器体验增强

- **括号匹配高亮**：`Document::bracket_pair` 从光标处（优先）或光标左侧字符出发，
  按同类型括号的嵌套深度向对应方向扫描，返回括号与配对位置；
  扫描上限 4000 行 / 50 万字符，避免超大单行每帧卡顿。
  渲染层在文本网格中把两处括号底色替换为强调色，TUI 与 GUI 共用。
- **粘性滚动**：`sticky_line` 从当前首行按缩进向上查找作用域首行（最多 500 行），
  命中后在外层面包屑行显示 `⋯ 外层代码`，不遮挡正文；`sticky_scroll = false` 可关闭。
- **自动保存**：`tick` 中检测 `last_edit` 是否已空闲 2 秒，满足则对
  已命名、非只读、非 Word/Excel/图片的脏标签调用 `save_document`；
  `autosave = false`（默认）时不启用。
- **会话恢复**：`ui/session.rs` 读写 `%APPDATA%\Textm\session.ini`
  （`fileN = 行号\t列号\t路径` 与 `active`），退出时在 `finish_quit` 记录，
  无命令行文件启动时由 TUI/GUI 入口调用 `restore_session` 重新打开并定位光标；
  `restore_session = false` 可关闭。

## 4. SCM（Git）集成的技术栈

### 4.1 方案对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 调用 `git.exe`（当前） | 零依赖、行为与命令行完全一致、支持所有特性 | 需要系统安装 Git | 本项目采用 |
| libgit2（`git2` crate） | 进程内、性能好 | 引入 C 依赖，违背零依赖 | 不采用 |
| `gix`（纯 Rust） | 无 C 依赖 | 依赖树大、编译慢 | 不采用 |
| 自研 Git 对象层 | 极致可控 | 工作量巨大，兼容性风险 | 不采用 |

### 4.2 当前实现

`vcs/git.rs` 用 `std::process::Command` 调用系统 Git（`CREATE_NO_WINDOW` 隐藏控制台）：

- `git rev-parse --show-toplevel` 发现仓库；
- `git rev-parse --abbrev-ref HEAD` 取分支；
- `git status --porcelain` 取变更列表（侧边栏 Git 面板、状态栏分支）；
- `git show HEAD:<文件>` 取基线文本，与当前行做 LCS 差异，生成**行内边条**
  （新增/删除/修改）；
- `git diff -- <文件>` / `git diff --cached -- <文件>` 生成工作区 / 暂存区差异；
- `git add -- <文件>` / `git reset -q HEAD -- <文件>` 暂存与取消暂存；
- `git add -A` / `git reset -q HEAD` 全部暂存 / 全部取消暂存；
- `git checkout -- <文件>` 丢弃未暂存改动（丢弃后重新载入已打开文档）；
- `git branch --no-color` 列出分支，`git checkout <分支>` 切换；
- `git blame --date=short -- <文件>` 生成逐行 Blame；
- `git log --oneline --decorate -n 100` 显示历史，回车查看某次提交的 `git show`；
- `git add -A && git commit -m` 提交。

面板交互（`ui/git_panel.rs`）：↑↓ 选择、Space 暂存/取消暂存、Enter 差异、
A/U 全部暂存/取消、c 提交、D 丢弃、b 分支、l 历史、r 刷新。
命令面板 / Git 菜单另提供：`git pull --ff-only`、`git push`、`git fetch --all --prune`、
`git stash push -u`、`git stash pop`、`git switch -c <分支>`、`git branch -d <分支>`、
`git merge --no-edit <分支>`；所有 git 调用统一设置 `GIT_TERMINAL_PROMPT=0` 与
`GIT_PAGER=cat`，缺少凭据时直接返回错误而不是阻塞界面。

### 4.3 扩展路线

- 差异边条点击跳转到对应 hunk，支持按 hunk `git apply --cached`；
- 冲突解决：检测 `<<<<<<<` 并高亮，提供接受当前/对方操作；
- 远程：`git fetch/pull/push`，凭据交给系统 Git Credential Manager；
- 提交图：解析 `git log --graph` 生成分支拓扑。

## 5. LSP 与智能补全

- `lsp/json.rs`：自研 JSON 解析/序列化（含 `\uXXXX` 转义）。
- `lsp/client.rs`：
  - `Command` 启动语言服务器，`stdin/stdout` 管道；
  - `Content-Length: N\r\n\r\n` 分帧；
  - 后台线程读取消息：`textDocument/publishDiagnostics` 存入按文件索引的诊断表，
    响应按 `id` 交给等待方；
  - 初始化 → `initialized` → `didOpen` / `didChange` → 各类请求；
  - 请求前先 `sync(path, text)`，保证服务器看到的是编辑器当前内容（含未保存修改）。
- 已实现的请求：
  - `textDocument/completion`：支持 `CompletionList` / 数组，优先 `textEdit.newText`，
    其次 `insertText`，最后 `label`；
  - `textDocument/hover`：解析 `MarkupContent.value`、字符串、`MarkedString[]`；
  - `textDocument/definition`：跳转到定义；`Alt+F12` 用同一结果做定义预览，
    读取目标文件上下文后放入浮层（Enter 跳转）；
  - `textDocument/references`：引用列表，回车跳转；
  - `workspace/symbol`：工作区符号搜索（Ctrl+T），按 SymbolKind 显示中文类型，
    回车跳到对应文件与行列；
  - `textDocument/rename`：解析 `changes` 与 `documentChanges`，按文件分组应用；
    打开的文件走 `replace_ranges_each`（可撤销），未打开的文件直接写盘；
  - `textDocument/formatting`：`tabSize` / `insertSpaces`，编辑可跨行；
  - `textDocument/signatureHelp`：解析 `signatures[].label` 与 `documentation`
    （`activeSignature` 越界时收敛）；输入 `(` / `,` 自动触发，或 Ctrl+Shift+Space；
  - `textDocument/codeAction`：上下文携带与当前行重叠的诊断，解析 `edit`
    （`changes` / `documentChanges`），忽略只有 command 没有 edit 的项；
    列表回车后用 `lsp_apply_edits` 批量应用；
  - `textDocument/inlayHint`：`label` 支持字符串与分段数组，`paddingLeft` / `paddingRight`
    转成前后空格，UTF-16 列换算为字符列后按行缓存，最多 2000 条。
- 自动触发策略（`app.rs::tick` / `note_lsp_input`）：
  - `LspState::active_for` 只在该语言已有运行中的服务器时返回 true，
    因此输入不会触发进程启动；首次连接仍靠手动命令；
  - 自动补全：输入标识符（字母/数字/`_`/`$`）后 260ms 无输入、单光标无选区、
    前缀 ≥ 2 时静默打开补全列表（`lsp_auto_complete`）；
  - 签名帮助：`(` / `,` 后请求（`lsp_signature_help`），光标离开触发行或 Esc 隐藏；
  - 内联提示：停止输入 500ms 且文件版本变化时拉取（`lsp_inlay_hints`），
    在 `draw_text` 中按列插入浅色文本并推进绘制列。
- 列号在编辑器字符列与 LSP UTF-16 code unit 之间转换（`utf16_col` /
  `utf16_to_char`）；文本编辑的字节偏移由 `text_offset` 计算。
- 服务器命令来自配置：`lsp.rust = rust-analyzer`、`lsp.python = pylsp` 等；
  未安装时安静降级，状态栏提示。
- 补全回退：没有可用语言服务器时，从当前文档与其他已打开文档收集同前缀标识符
  （长度 ≥ 2、最多 200 个），保证纯文本、自定义语言也能补全。
- 多语言：内置 Rust / Python / JavaScript / TypeScript / Go / C / C++ 的默认命令，
  其他语言（含自定义语言）都可通过 `lsp.<语言显示名>` 配置。

## 6. 插件、调试与远程开发

### 6.1 自有插件系统（extension.rs + plugin/）

- 目录：`%APPDATA%\Textm\plugins\<名称>\textm.json` 与
  `<工作区根>\.textm\plugins\<名称>\textm.json`。
- 清单字段：`name/version/description/main/activation/commands/themes/snippets`；
  `commands[i] = { id, title, program?, args?, cwd? }`。
  `program` 存在时是声明式命令（任务运行器执行），否则由 `index.js` 注册。
- 启用状态保存在 `config.ini` 的 `plugins_disabled`；总开关 `plugins_enabled`
  默认 false，关闭时菜单、命令、主题、片段与 JS 宿主全部停用。
- 声明式贡献：`themes` 指向自有主题 JSON（`bg/fg/panel/accent/syntax` 等），
  `snippets` 指向 `{名称:{language,body}}` JSON；加载时注册进 Theme / Snippet 全局表，
  关闭插件时用 `theme::unregister` 与 `snippets::clear_market` 撤销。
- JS 宿主（`plugin/mod.rs`）：
  - Boa `Context` 懒创建；`textm.js` 定义 `textm` API 与 CommonJS 模块加载；
  - 需要触达编辑器的能力以请求队列交给 UI 线程（QuickPick / 输入框 / 编辑 /
    打开 / 保存 / 终端 / 面板 / 问题列表），JS 侧通过 Promise 等待结果；
  - 命令在 `onCommand` 时懒激活（或清单声明 `activation:["startup"]`）；
  - `save` / `open` / `change` 事件由 App 通过 `__textmFire` 注入；
  - 引擎在独立的大栈线程上运行（32 MB），避免解析深层脚本时栈溢出。

### 6.2 调试器（debug.rs）

- `launch.json` 解析：只取 `configurations[]`，保留整份配置对象；
  启动前递归展开 `${workspaceFolder}`、`${file}`、`${fileBasename}`、
  `${fileDirname}`、`${env:NAME}` 等占位符。
- 适配器命令来自 `config.ini` 的 `debug.<type>`；内置默认 `python`/`debugpy`
  → `python -m debugpy.adapter`，`lldb`/`dap` → `lldb-dap`。
- 传输：`DapClient` 启动适配器进程，stdin 写请求、stdout 由后台线程按
  `Content-Length` 帧解析到队列，主线程在 `tick` 中 drain（不阻塞 UI）；
  stderr 与事件日志进入共享环形缓冲（最多 4000 行）。
- 会话状态机：
  - `initialize` 应答 → 按配置 `request` 发送 `launch` 或 `attach`；
  - `initialized` 事件 → `setBreakpoints`（按文件汇总，行号 +1）→
    `setExceptionBreakpoints` → `configurationDone`；
  - `stopped` 事件 → 记录 threadId，请求 `stackTrace`；
    应答后取首帧跳转（`open_debug_location`），再 `scopes` → `variables`；
  - `output` 事件按行写入日志；`terminated` / `exited` 触发 `shutdown`。
- 断点存在 `BTreeMap<PathBuf, BTreeSet<usize>>`，内部 0 基、发送时 1 基；
  F9 切换后若会话已建立会立即重发 `setBreakpoints`。
- 渲染：`draw_gutter` 用红点标断点、`▶` 标当前栈帧行；状态栏追加调试状态。

### 6.3 远程开发（remote.rs）

- UNC/SMB 直接作为工作区根（复用多根 Sidebar），文件搜索与任务运行天然覆盖。
- SSH 主机解析 `[user@]host[:port]`，可选 `remote.<名称>.root` 作为默认目录；
  使用系统 `ssh.exe` / `scp.exe`，统一 `BatchMode=yes`、`ConnectTimeout=10`。
- 远端命令构造为 `Task { command: "ssh", args: [...] }`，复用任务输出面板；
  远端目录经 shell 单引号转义后以 `cd '<root>' && <command>` 执行。
- 远端文件：`scp` 下载到 `%APPDATA%\Textm\remote\<主机>\<远端路径>`，
  按 `本地缓存路径 → (主机, 远端路径)` 记录映射；`Ctrl+S` 成功后自动 `scp` 回传。
- 缓存路径按段清洗（只保留字母数字与 `._-@`），阻止 `..` 越界。

## 8. 已知限制

- GUI 使用 GDI 渲染（非 DirectWrite），复杂连字由字体本身决定；
- TUI 图片默认半块字符，Sixel/Kitty 协议尚未启用（代码预留）；
- Word 高保真分页只在 GUI 页面视图呈现；文本视图不编辑表格内文字（保存时原样保留）；
- Word 不支持编辑图片、脚注与批注正文（批注仅读取）；
- Excel 公式为常用子集，不支持数组公式、跨工作簿引用；图表/透视表只保留不编辑；
- 工程搜索/替换支持跨行正则；UTF-16 文件可参与搜索，其他含 NUL 字节的二进制文件会被跳过；
- `.gitignore` 只读取工程根目录的一份，不递归读取子目录；`workspace_include` /
  `workspace_exclude` 为 glob 过滤（`*` 不跨目录、`**` 跨目录）；
- Git 功能依赖系统 `git.exe`；LSP 依赖外部语言服务器；
- LSP 自动补全 / 签名帮助 / 内联提示依赖语言服务器已连接，首次连接需手动触发；
- 插件使用内嵌 Boa：只支持自有 textm API 与相对路径 require，不支持 Node 内置模块 / npm；
  异步仅 Promise 与 setTimeout，不保证完整 ES2022；插件功能默认关闭；
- DAP 实现为常用子集（断点、继续、单步、调用栈、变量），不支持条件断点、数据断点、
  反向调试；适配器需要用户自行安装；
- 远程文件采用“下载到本地缓存 + 保存回传”，不是远端文件系统挂载；
  SSH 使用 `BatchMode=yes`，需提前配置密钥；
- 超大文件（数十万行）高亮按行缓存，内存占用随文件增长。
